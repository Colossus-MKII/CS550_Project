1. YOLO：目标检测

我们加载已经训练好的 yolo11s-seg.pt。对每一帧，它预测目标类别、位置、检测置信度，以及分割掩码。第一课先隐藏掩码，只观察框。

@@VIDEO_BOXES@@
  1. 读取与缩放。OpenCV 解码视频，保持连续帧及原始帧率；长边按设置缩小，写成统一输入帧。缩放是减少像素量，不是 YOLO 必须要求“先压缩视频”。
  2. 准备模型输入。库负责调整输入尺寸与填充、通道顺序、张量转换和归一化。外部视频缩放与模型内部预处理是两件事。
  3. 提取特征与预测。神经网络根据训练中学到的形状、纹理和上下文，预测目标框、类别及分数；不是从数据库里逐张找相同图片。
  4. 过滤结果。按类别和置信度筛选，再通过非极大值抑制（NMS）等后处理减少重复框。阈值太高可能漏掉困难目标，太低则可能增加误检。
  5. 绘制结果。模型输出数值；plot() 将框、标签和分数绘制到画面上。
① 导入工具，加载权重。两个 YOLO 实例用于隔离普通预测与有状态跟踪，都是同一个权重文件。

ultralytics 是第三方 Python 库，封装了 YOLO 模型的加载、预测、训练和跟踪接口。它基于 PyTorch，不是 Python 内置包。

@@CODE_MASK@@

prediction.boxes 保存类别、框和置信度；prediction.masks.data 保存各实例的 mask。同一帧中第 i 个框对应第 i 张 mask，但这个数组下标不是跨帧身份编号。

掩码是怎样预测出来的？

分割模型有专门的输出分支，利用图像特征预测目标区域。它不是简单地把检测框填满，也不是只沿颜色变化机械描边。

Mask 原型与组合系数

我们使用的实现会从当前图像特征生成一组共享的 mask 原型，再预测每个目标的组合系数，组合、调整尺寸并裁剪得到目标 mask。原型是当前图像相关的特征表示，不是一组固定“狗形状模板”。

retina_masks=True 让输出掩码按所传入画面的尺寸对齐，方便叠加和统计；这个开关不意味着模型自动获得更强的识别能力。

3. ByteTrack：多目标跟踪

YOLO 负责检测与分割，ByteTrack 负责关联检测框并维护 ID。画面中显示 id:2 dog 0.73 时，2 是轨迹编号，dog 是类别，0.73 仍然是检测分数，不是身份匹配概率。

@@VIDEO_TRACK@@

不是大模型，也不只是卡尔曼滤波器

  1. 运动预测：它应该在哪里？每条轨迹维护自己的卡尔曼状态，根据框的位置、尺寸及变化趋势预测下一帧。找到新观测后再修正状态与不确定性。这不是训练神经网络。
  2. 数据关联：哪个框对应它？用预测框与新检测框的 IoU 等信息计算匹配代价，再做整体一对一匹配。卡尔曼滤波本身不负责决定多个新框分别属于谁。
  3. 两阶段匹配：先高分，再低分。先用高置信度检测匹配已有轨迹；再用部分低置信度框接续尚未匹配的活动轨迹。被遮挡的狗可能只剩一个低分框，但其位置与已有轨迹相符，仍有机会接上。
  4. 轨迹管理：记住多久？新目标建立 ID；短暂丢失先保留；超过保留期限结束旧轨迹。回来后无法接上旧轨迹，就可能建立新编号。

ByteTrack 也有历史记忆：过去的观察融合为位置、速度与不确定性，并保留轨迹状态。它没有标准外观 ReID，不能仅凭毛色找回很久以前的狗。项目将比较它的历史保留与运动状态重初始化，而不是把 ByteTrack 当作“无记忆”组。

当前配置：高分门槛 0.25、低分门槛 0.1，丢失轨迹保留约 30 帧；这些参数可调整。

代码里的关键参数

tracked = tracker.track(
    frame, persist=True, tracker="bytetrack.yaml", **options
)[0]

tracker 是一个 YOLO 对象；track() 内部先运行 YOLO，再运行关联器。persist=True 保留前面帧的状态。读取 box.id 获取编号。我们为教学对比独立调用一次 predict()、一次 track()，不是把前者返回值直接传给后者。

为什么不能把 YOLO 置信度门槛随便调高？

如果 YOLO 已在前面丢弃置信度 0.18 的框，ByteTrack 的低分匹配阶段就再也看不到它。教程默认较低的检测阈值，是为了保留这类候选，但也会引入更多背景候选。阈值应在验证集上选择。

实际案例：狗从 ID 2 变成 ID 6

我们讨论的原始狗视频运行中，狗先对应 ID 2，离开画面后跟踪中断，回来时成为 ID 6；人保持 ID 1。中断超过了约 30 帧的保留长度，与当前轨迹管理配置相符。数字跳到 6 不代表出现了六只狗。

这段话是对那次视频的案例分析。下方「逐帧证据」直接读取当前运行的日志，换视频后不要照搬原来的 ID 或帧号。

ReID 与事件推理

当前 ByteTrack 实现主要利用位置、运动与检测分数，没有外观重识别（ReID）网络，也没有“扔球—追球—叼球返回”的事件理解模块。

如果人扔球，狗跑出画面又叼球回来，能作为同一只狗的证据吗？

扔球、追球、叼球返回的行为链，加上外观、方向和时间间隔，可以支持同一身份的推断，但不能替代逐帧身份标注。ReID 补充外观线索；动作与事件推理需要额外模块，当前两套流程均未实现。

数学展开：卡尔曼公式与两阶段匹配。

4. SAM 2.1：提示式视频分割

本项目使用预训练的 SAM 2.1 Hiera Tiny。YOLO 检测预定义类别的目标；SAM 根据指定目标的空间提示生成并传播 mask，不直接输出类别名。

@@VIDEO_SAM@@

第一帧的提示从哪里来？

本教程自动模式中，YOLO 提供第一帧目标框，程序为选中的目标分配编号，然后把框交给 SAM。手动模式也可以自行选框。此后向前传播时，没有每帧用 YOLO 重新提示。

@@PROMPT@@

提示可以是点、框或 mask；这里不是发送“dog”这个文字指令。视频上显示的 dog 标签由程序从初始化来源保存，不是 SAM 接口自己输出的类别名。

视觉记忆怎样工作？

  1. 读取当前画面。图像编码器提取空间、形状和纹理等视觉特征。
  2. 参考历史记忆。记忆注意力将当前特征与提示帧、部分历史帧的目标相关信息联系起来。
  3. 预测当前 mask。掩码解码器结合当前图像、提示与记忆，输出此刻的目标区域。
  4. 更新记忆。把预测与视觉特征编码，供后续帧使用。

传播结合当前画面与历史视觉特征，不是简单平移上一帧 mask。记忆更新改变推理状态，不更新模型权重。

为什么 ID 一直是 2，也不能证明始终跟对了？

SAM 的 ID 2 是目标槽位，由我们初始化。即使预测漂移到了另一只狗或背景，仍然可能输出 ID 2。必须检查该 ID 下的 mask 是否对应正确目标，而不是只看编号有没有变化。

在讨论过的狗视频中，第 90 帧目标 2 的 mask 为空；到第 106、119 帧又出现，并在最后的样例帧覆盖返回的狗。这是有用观察，但没有标准标注仍不能据此计算身份准确率。

中途出现新目标怎么办？

当前脚本只初始化第一帧目标。SAM 支持追加提示，但自动发现新目标需要额外逻辑。正式方案计划定期运行 YOLO，匹配旧目标、初始化新目标，并管理提示更新和失效轨迹。

数学展开：提示编码、注意力与记忆。

相同纠正机会下的四组实验

实验组历史处理同一纠正框的作用
A-H保留 ByteTrack 运动状态执行一次正常卡尔曼更新
A-R重建 ByteTrack 运动状态框初始化、零速度、默认初始协方差
B-H保留 SAM 目标历史向已有目标追加框提示
B-R清除该目标旧推理状态以相同框重新初始化

H 组也接收纠正。每套系统的 H/R 共享纠正前的历史，保留外部 ID，统一生命周期处理，冻结权重。纠正框只消费一次；纠正后继续正常检测与提示安排，不追加人工或标注帮助。人为固定目标对应关系只用于这项诊断，不混入自动基线成绩。

先配对，再解释不同机制

分别比较 A-H/A-R 与 B-H/B-R，观察恢复是否发生、持续多久、后续观察是否消除差异。共同看指定目标的定位与持续正确跟随；A 另外看运动预测和关联，B 另外看掩码与漂移。不把两个不同系统的原始分数直接解释成记忆形式的净影响。

覆盖稳定跟随、遮挡、返回、突然运动变化及相似目标。主要四组事件要求双方仍有可保留状态；轨迹已删除等不适用事件另报数量与比例。窗口排除被直接纠正的当帧，固定外部 ID，缺失和空输出不忽略。

有可复核证据时，最多选择一项简单自动策略放回对应流程验证；无明显收益同样是结果。核心实验不进行 YOLO 或 SAM 权重微调。

IoU、IDF1 与 HOTA

先有标准答案（Ground Truth）：每帧的目标类别、mask，以及跨帧真实身份。再将预测与之匹配。模型自己给的置信度，不是对照标准答案后的成绩。以下质量指标通常在 0–1 之间，也常乘 100 显示；越高越好，但不是同一种百分比。

IoU：区域重合度

IoU = |预测区域 ∩ 标注区域| / |预测区域 ∪ 标注区域|

如果真实 mask 和预测 mask 各有 100 个像素，其中 80 个重合，并集是 100 + 100 − 80 = 120，所以 IoU = 80 / 120 ≈ 0.667，不是 0.8。它同时惩罚漏掉的目标像素和多涂出的背景像素。

实线：标注虚线：预测
IoU 0.667交集 6400 px并集 9600 px

box IoU 比矩形，mask IoU 比真实像素区域。框很准，不保证轮廓准。仅对匹配目标计算平均 mask IoU 会遗漏未检出的目标：十只狗只找到一只，找到的那只可能满分，剩下九只漏检却不在该均值中，不能只用它排名。正式指标见「项目实验设计」。

IDF1：全局身份匹配

IDF1 从整段视频建立真实身份与预测身份的一对一对应，再计算身份层面的正确、错误和遗漏。它不是逐帧比较数字是否一样：真实标注叫 A，预测始终叫 7，可以完全正确。

IDF1 = 2 × IDTP / (2 × IDTP + IDFP + IDFN)
  • IDTP：正确身份对应的目标出现次数。
  • IDFP：预测中没有正确对应真实身份的出现次数。
  • IDFN：真实目标没有得到正确身份对应的出现次数。

单位是“一个目标在一帧中的一次出现”，不是像素。它们也不一定等于普通检测的 TP / FP / FN。

十帧的一只狗。每帧 mask 都完美，前五帧叫 7，后五帧叫 8。全局一对一身份匹配只能选一段，得到 IDTP = 5、IDFP = 5、IDFN = 5，IDF1 = 0.5。像素全对，身份仍然被拆断。

我们的计划在 mask IoU 0.5 下计算 IDF1，匹配细节遵循统一 TrackEval 适配器。保持 ID 不变但位置完全错误，不能得高分。门槛之上的轮廓差异也未必被 IDF1 充分区分，因此正式实验还会报告多阈值 mask HOTA，并单独检查 YOLO 的框与掩码 AP50:95。

HOTA：检测与关联质量

DetA 关注找到了多少目标、漏了多少、多报了多少；AssA 关注轨迹关联是否正确，包括把同一目标拆开、把不同目标混成一个。AssA 不等于 IDF1，也不是“1 − ID 切换率”。

DetA(α) = TP / (TP + FP + FN)
HOTA(α) = √[DetA(α) × AssA(α)]

α 是评分时要求的重合门槛，不是 YOLO 的置信度。标准 HOTA 对 0.05、0.10……0.95 共 19 个门槛分别计算，再平均这些 HOTA 值；不是先平均 DetA、AssA 再开方。轮廓不准，会在较高门槛下失去匹配，因此定位质量也影响最终评分。

在刚才的五帧 + 五帧例子中，检测全对，DetA = 1；每个预测 ID 只覆盖真实轨迹的一半，AssA = 0.5。因此 HOTA ≈ 0.707。它与 IDF1 的 0.5 并不矛盾：评价方式不同。

为什么“狗在画面外没有 mask”不一定是漏检？

漏检要对照标注定义。如果那一帧没有可评估的可见目标 mask，不输出 mask 通常正确。反过来，目标消失后还把地面涂成狗，可能是误检。模型内存里保留轨迹，与画面中必须输出目标是两件事。

为什么光看“ID 有没有变”不够？

同一个 ID 可能错误地从狗 A 跑到狗 B；编号不变，但身份关联错了。IDF1 / HOTA 通过与真实轨迹对应来判断，不能用“数字始终是 2”替代标注评分。ID 切换次数也要遵循评估器的连续性与匹配规则，不能随意自写计数再叫标准指标。

FPS 与显存

FPS = 处理帧数 / 耗时。正式计时需统一包含解码、预处理、检测、提示创建、传播 / 关联与后处理，排除并注明模型加载、渲染和评分；统一 GPU、输入、精度与预热，进行 GPU 同步，重复三次取中位数。

PyTorch allocated、reserved 与驱动报告的进程显存不是一个数。CPU offload 节省显存但占用内存并可能影响速度。当前日志是冷启动诊断，不是正式性能排名；播放器的 30 FPS 更不等于模型推理 30 FPS。

参考掩码与目标编号

第一帧里，SAM 勾出人和狗。程序把背景设为 0、人的像素设为 1、狗的像素设为 2。DeAOT 接收第一帧图像和这张带编号的参考掩码，再预测后续帧中两个目标的像素区域。

DeAOT 的“解耦”是什么？

它把一般视觉信息与目标特定的身份信息放在不同分支中传播。通俗地说，同时保留“这里长什么样”和“这里属于初始化的哪个目标”，避免传播身份时损失有用的视觉信息。这是对内部表示的简化解释，不是两个独立分类器。

参考掩码不好、遮挡、相似目标或累积误差都可能造成漂移；模型不会因为运行起来就自动获得任意新物体的项目级身份。

“半监督视频分割”是不是每个视频都要重新训练？

这个任务名称通常指推理时提供参考帧标注（常见为第一帧 mask），随后预测其他帧。它不意味着每个新视频都要微调模型。使用冻结预训练权重也可以完成这类任务；是否训练是另一个决定。

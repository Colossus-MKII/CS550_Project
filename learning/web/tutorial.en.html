1. YOLO: Object Detection

We load the pretrained yolo11s-seg.pt checkpoint. For each frame, it predicts object classes, locations, detection confidence scores and segmentation masks. In lesson one, we hide the masks to focus on boxes.

@@VIDEO_BOXES@@
  1. Read and resize. OpenCV decodes the video, preserving consecutive frames and the source frame rate. The long edge is resized according to our settings, producing a consistent set of input frames. Resizing reduces pixel count; YOLO does not require us to “compress the video first.”
  2. Prepare the model input. The library handles input sizing and padding, channel order, tensor conversion and normalization. Resizing the source video and preprocessing inside the model pipeline are separate steps.
  3. Extract features and predict. The network uses learned shape, texture and context cues to predict boxes, classes and scores. It does not search a database for an identical image.
  4. Filter the output. Class and confidence filters, followed by postprocessing such as non-maximum suppression (NMS), reduce duplicate boxes. A high threshold can miss difficult objects; a low threshold can introduce false detections.
  5. Render the output. The model returns numerical predictions; plot() draws boxes, labels and scores on the frame.

Read a detection result

dog · 0.73 · [x1, y1, x2, y2] means the model classifies this rectangle as a dog with a detection score of about 0.73. The coordinates are its top-left and bottom-right corners, in input-image pixels. 0.73 does not mean “73% of pixels are correct” or “73% confidence this is the previous dog.”

2. YOLO: Instance Segmentation

Each instance has its own mask. The simplest representation is a two-dimensional array aligned with the image: 1 means predicted foreground for this object, and 0 means everything else. The translucent color is for display only.

@@VIDEO_MASKS@@

YOLO segmentation output

The seg in yolo11s-seg.pt indicates segmentation support. Lessons one and two use the same prediction, with different display settings:

@@CODE_MASK@@

prediction.boxes stores classes, boxes and confidence; prediction.masks.data stores instance masks. Within one frame, box i corresponds to mask i, but this array index is not an identity across frames.

How is a mask predicted?

A dedicated output branch uses image features to predict object regions. It does not simply fill the detection box or mechanically trace every color boundary.

Mask prototypes and coefficients

This implementation generates shared mask prototypes from the current image features and predicts combination coefficients for each object. Combining, resizing and cropping produces the instance masks. The prototypes are image-dependent feature representations, not fixed “dog-shaped templates.”

retina_masks=True aligns the output masks to the dimensions of the supplied frame, simplifying overlays and statistics. This setting does not automatically give the network better recognition ability.

Why is mask_pixels not accuracy?

When saving results, we count the foreground pixels in each mask:

@@CODE_RECORDS@@

(mask > 0.5).sum() here counts positions equal to 1 in a binary mask; it is not filtering detection confidence again. An increase in area could mean the object moved closer, or that the prediction included more background. Without ground truth, area alone cannot establish accuracy.

Boundary errors: legs, tails and thin objects

Pause near legs, tails and thin objects. Check for missing foreground and included background. In frame 60 of the dog run we discussed, the YOLO dog mask included some ground between the legs. That observation belongs to that run, not necessarily other videos or frames.

3. ByteTrack: Multi-Object Tracking

YOLO detects and segments; ByteTrack associates detection boxes and maintains IDs. In id:2 dog 0.73, 2 is the track ID, dog is the class, and 0.73 is still a detection score—not the probability of a correct identity match.

@@VIDEO_TRACK@@

Not a large neural model—and not just a Kalman filter

  1. Motion prediction: where should it be? Each track maintains its own Kalman state. Box position, size and their changes predict the next frame. New observations correct the state and uncertainty. This is not neural-network training.
  2. Data association: which box belongs to it? IoU between predicted and newly detected boxes, and other configured information, defines matching costs for a global one-to-one assignment. A Kalman filter alone does not decide which of several new boxes belongs to which object.
  3. Two-stage matching: high scores, then low scores. High-confidence detections are matched first. Some lower-confidence boxes then help recover unmatched active tracks. An occluded dog may yield only a low-score box, but its location can still agree with an existing track.
  4. Track management: how long to remember? New objects get IDs. Lost tracks are retained briefly, then removed after a timeout. A returning object that cannot reconnect may receive a new ID.

ByteTrack also has historical memory: previous observations are summarized in position, velocity, uncertainty and track state. Standard ByteTrack has no appearance-ReID network that retrieves an old dog from its coat pattern. Our project compares retention with motion-state reinitialization; ByteTrack is not a “no-memory” group.

Current settings: high-score threshold 0.25, low-score threshold 0.1, and roughly 30 frames of lost-track retention. These parameters are configurable.

The important code settings

tracked = tracker.track(
    frame, persist=True, tracker="bytetrack.yaml", **options
)[0]

tracker is a YOLO object. track() runs YOLO internally and then performs association. persist=True retains state from earlier frames, and box.id exposes the ID. For the teaching comparison, we call predict() and track() independently; we do not pass the first call's returned detections directly into the second.

Why not simply raise the YOLO confidence threshold?

If YOLO already discards a box with confidence 0.18, ByteTrack's low-score matching stage can never see it. Our low detection threshold preserves these candidates, but can also admit more background detections. Choose thresholds on a validation set.

Real case: the dog changes from ID 2 to ID 6

In the original dog run we discussed, the dog starts as ID 2, leaves the image and loses its track, then returns as ID 6. The person keeps ID 1. The gap exceeds the roughly 30-frame retention window, consistent with the current track-management settings. Jumping to ID 6 does not mean six dogs appeared.

This is a case study of that particular video. The frame evidence below reads the current run's logs directly. Do not reuse the old IDs or frame numbers when changing videos.

ReID and event reasoning

Our ByteTrack implementation primarily uses location, motion and detection scores. It has no appearance re-identification (ReID) network and no event-understanding module for “throw ball → chase → return carrying ball.”

Can throwing a ball and seeing a dog return with it support an identity inference?

The throw–chase–retrieve sequence, appearance, direction and elapsed time can support an identity inference, but cannot replace frame-level identity annotations. ReID adds appearance cues; action and event reasoning requires additional modules. Neither project pipeline implements event reasoning.

4. SAM 2.1: Promptable Video Segmentation

We use pretrained SAM 2.1 Hiera Tiny. YOLO detects predefined object classes; SAM generates and propagates masks from spatial prompts specifying a target. SAM does not directly output class names.

@@VIDEO_SAM@@

Where does the first-frame prompt come from?

In this tutorial's automatic mode, YOLO supplies first-frame boxes. The program assigns IDs to selected objects and passes the boxes to SAM. Manual mode also lets you choose boxes. Forward propagation then proceeds without fresh YOLO prompts on every frame.

@@PROMPT@@

Prompts can be points, boxes or masks. We are not sending the text instruction “dog.” The displayed dog label is saved by our program from the initialization source; it is not a class name produced by the SAM interface.

How does visual memory work?

  1. Read the current image. The image encoder extracts spatial, shape and texture features.
  2. Consult past memory. Memory attention connects current features with object-related information from prompted frames and selected past frames.
  3. Predict the current mask. The mask decoder combines image features, prompts and memory to predict the target region now.
  4. Update memory. Predictions and visual features are encoded for use by later frames.

Propagation combines the current image with past visual features rather than translating the previous mask. Memory updates change inference state, not model weights.

Why does keeping ID 2 not prove correct tracking?

SAM's ID 2 is an object slot initialized by us. A prediction that drifts to another dog or the background can still be labeled ID 2. Inspect whether the mask under that ID covers the correct object, not just whether the number changes.

In the dog video we discussed, object 2 has an empty mask at frame 90. It reappears at frames 106 and 119, covering the returning dog in the final sample frame. This is a useful observation, but does not provide identity accuracy without ground truth.

What happens when a new object enters?

The current script initializes only first-frame objects. SAM accepts additional prompts, but automatic discovery requires extra logic. The formal design adds periodic YOLO detection, matching to existing objects, new-object initialization, prompt updates and lost-track management.

Pair first, then interpret different mechanisms

Compare A-H/A-R and B-H/B-R separately: does recovery occur, how long does it last, and do subsequent observations erase differences? Both measure localization and sustained correct following. A also diagnoses motion and association; B diagnoses masks and drift. Raw cross-system scores do not isolate the effect of memory representation.

Cover stable following, occlusion, re-entry, sudden motion changes and similar distractors. Primary four-group events require retained state in both systems; report counts and proportions of deleted-track or other ineligible cases separately. Exclude the directly corrected frame, keep the designated external ID fixed and count missing or empty outputs.

If reproducible evidence supports it, select at most one simple automatic policy for validation in its pipeline. No-benefit outcomes are valid results. Core experiments do not fine-tune YOLO or SAM weights.

How do inference, parameter selection and fine-tuning differ?

Inference: Process new inputs with frozen weights. Parameter selection: Choose pipeline settings such as confidence, matching thresholds and discovery intervals. Fine-tuning: Update neural-network weights using training data. Updating a Kalman state or SAM's video memory is not weight fine-tuning.

IoU, IDF1 and HOTA

Start with Ground Truth: per-frame object classes, masks and identities across frames. Match predictions against these annotations. A model's confidence is not a score obtained by comparing it with ground truth. These quality metrics generally range from 0 to 1, often multiplied by 100 for display. Higher is better, but they are not the same kind of percentage.

IoU: region overlap

IoU = |prediction ∩ ground truth| / |prediction ∪ ground truth|

If a ground-truth mask and a predicted mask each contain 100 pixels and share 80, the union is 100 + 100 − 80 = 120. IoU = 80 / 120 ≈ 0.667, not 0.8. It penalizes both missing foreground pixels and extra background pixels.

SYNTHETIC LAB A

Move the prediction; watch intersection and union

This simplified example uses 100 × 80 pixel rectangles. Real mask IoU applies the same formula to pixel sets of any shape.

Solid: ground truthDashed: prediction
IoU 0.667Intersection 6400 pxUnion 9600 px

Box IoU compares rectangles; mask IoU compares pixel regions. An accurate box does not guarantee an accurate contour. Mean mask IoU over matched targets excludes undetected objects: if only one of ten dogs is found, that one may receive a perfect score while the nine misses are excluded. Do not rank systems by this alone. Chapter 7 lists the formal evaluation protocol.

IDF1: global identity matching

IDF1 establishes a global one-to-one correspondence between ground-truth and predicted identities over the video, then counts identity-level correct matches, errors and omissions. It does not compare ID numbers literally: ground-truth A can correctly correspond to predicted ID 7 throughout.

IDF1 = 2 × IDTP / (2 × IDTP + IDFP + IDFN)
  • IDTP: Object appearances with a correct identity correspondence.
  • IDFP: Predicted appearances without a correct ground-truth identity correspondence.
  • IDFN: Ground-truth appearances without a correct predicted identity correspondence.

The unit is one object's appearance in one frame, not pixels. These counts need not equal ordinary detection TP / FP / FN.

One dog over ten frames. Every mask is perfect, but the first five frames use ID 7 and the last five use ID 8. Global one-to-one identity matching can select only one segment: IDTP = 5, IDFP = 5, IDFN = 5, so IDF1 = 0.5. Perfect pixels can still have fragmented identity.

Our plan evaluates IDF1 at mask IoU 0.5, following the common TrackEval adapter's matching rules. An unchanged ID at the wrong location cannot score well. IDF1 may not fully distinguish contour differences above that threshold, so the formal study also reports multi-threshold mask HOTA and standalone YOLO box/mask AP50:95.

HOTA: detection and association quality

DetA measures correctly detected, missed and extra objects. AssA measures association quality, including splitting one object across tracks or merging different objects into one. AssA is neither IDF1 nor “1 − ID-switch rate.”

DetA(α) = TP / (TP + FP + FN)
HOTA(α) = √[DetA(α) × AssA(α)]

α is the required overlap threshold for evaluation, not YOLO confidence. Standard HOTA is computed at 19 thresholds from 0.05 to 0.95 in steps of 0.05, then those HOTA values are averaged. It is not the square root of averaged DetA and AssA. Poor contours lose matches at higher thresholds, so localization quality affects the final score too.

In the five-plus-five-frame example, all detections are correct, so DetA = 1. Each predicted ID covers only half the true track, so AssA = 0.5 and HOTA ≈ 0.707. This does not contradict IDF1 = 0.5: they evaluate identity differently.

Why is “no mask while the dog is outside the image” not necessarily a miss?

Misses are defined against annotations. If there is no evaluable visible-object mask in a frame, emitting no mask is usually correct. Conversely, marking the ground as a dog after it disappears can be a false positive. Retaining a track in memory does not require emitting a visible object in every frame.

Why is checking whether the ID changes insufficient?

An unchanged ID can wrongly jump from dog A to dog B. The number is stable, but the association is wrong. IDF1 / HOTA compare against true trajectories; “it always says 2” cannot replace annotated evaluation. ID-switch counts must also follow the evaluator's continuity and matching rules, not an arbitrary custom count labeled as a standard metric.

FPS and GPU memory

FPS = processed frames / elapsed time. Formal timing should consistently include decoding, preprocessing, detection, prompt creation, propagation / association and postprocessing. Exclude and disclose model loading, rendering and scoring. Fix GPU, input, precision and warm-up; synchronize GPU work, repeat three times and report the median.

PyTorch allocated memory, reserved memory and driver-reported process memory are different measures. CPU offloading saves VRAM but consumes RAM and may affect speed. Current logs are cold-start diagnostics, not a formal speed ranking. A player showing 30 FPS does not mean the model infers at 30 FPS.

Reference masks and object IDs

SAM segments the person and dog in frame one. The program labels background pixels 0, person pixels 1 and dog pixels 2. DeAOT receives that image and identity-labeled reference mask, then predicts both objects' regions in subsequent frames.

What does “decoupling” in DeAOT mean?

General visual information and object-specific identity information propagate through separate branches. Intuitively, it retains both “what this region looks like” and “which initialized object it belongs to,” reducing loss of useful visual information while propagating identity. This is a simplified account of its internal representation, not two independent classifiers.

Poor reference masks, occlusion, similar objects and accumulated errors can cause drift. Simply running the model does not provide project-level identities for arbitrary new objects.

Does “semi-supervised video segmentation” require retraining on every video?

The task name usually means providing reference-frame annotations at inference time—often a first-frame mask—and predicting other frames. It does not mean fine-tuning on every new video. Frozen pretrained weights can be used for this task; whether to train is a separate decision.
